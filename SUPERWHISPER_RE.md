# Superwhisper iOS — reverse engineering notes

*Captured 2026-05-19 from the App Store IPA of Superwhisper v2.10.3 (bundle ID `com.superduper.superwhisper-ios`, team `XDP69BYUP9`) pulled via [ipatool](https://github.com/majd/ipatool). This is the architecture we want to clone to get "tap mic in keyboard → speak → text inserted, no app switch" on iOS 26.*

## TL;DR

Superwhisper's no-app-switch flow rests on **three pillars**, all needed together:

1. **iOS 18+ `AudioRecordingIntent` system protocol.** Their `ToggleRecordingIntent` conforms to this. `openAppWhenRun: false`. Apple lets an AppIntent that conforms to this protocol take over the mic from background, no foregrounding required.
2. **PushToTalk framework entitlement** (`com.apple.developer.push-to-talk: true`). Approved by Apple on application. Combined with `UIBackgroundModes: push-to-talk`, this is how the main app gets resumed from a suspended state when the keyboard signals it. Without this, the app must already be alive to handle the AppIntent.
3. **Shortcuts URL bridge.** The keyboard fires `shortcuts://run-shortcut?name=Toggle%20Superwhisper%20Recording` instead of `superwhisper://...`. Shortcuts is a system app so iOS allows keyboard extensions to open it. Shortcuts then runs the user-installed Shortcut which invokes the `AudioRecordingIntent` and copies the result to clipboard. Keyboard reads clipboard, inserts via `textDocumentProxy.insertText`.

The keyboard never opens the main app directly in the steady state — it opens Shortcuts, which runs the intent in the main app's process while the host app (Notes/Messages/whatever) stays foregrounded.

**Cold-start fallback** (no shortcut yet installed): keyboard fires `superwhisper://...` custom URL scheme, app opens, "Superwhisper is on, swipe back to keyboard" screen with an "install the shortcut to avoid this step" deep link. Why this `extensionContext.open` succeeds for them and fails for us is still open — most likely App Store / Distribution signing, possibly a trust heuristic from iOS recognising their bundle as established. Not blocking for the steady-state UX once the shortcut is installed.

### `Metadata.appintents/extract.actionsdata` — the App Intents manifest

This file is generated by Xcode at build time from `@AppIntent`-marked Swift types. It's the system's catalog of what intents an app exposes. **Superwhisper exposes exactly ONE intent.** Decoded:

```yaml
ToggleRecordingIntent:
  fullyQualifiedTypeName: superwhisper_ios.ToggleRecordingIntent
  title: "Toggle Recording"
  description: "Toggle a Superwhisper Recording"
  isDiscoverable: true
  openAppWhenRun: false                                              # ← runs in background
  presentationStyle: 0                                                # no UI
  systemProtocols:
    - com.apple.link.systemProtocol.AudioRecording                   # → AudioRecordingIntent (iOS 18+)
    - com.apple.link.systemProtocol.SessionStarting                  # → SessionStartingIntent
  parameters:
    - name: modeName
      type: String (optional)
      title: "Mode Name"
      isInput: false
    - name: releaseMic
      type: Bool
      title: "Release Mic Immediately"
      description: "Release the mic immediately instead of honoring the
                    app's session timeout."
      defaultValue: false
      isInput: false
  outputType: String                                                 # transcript

autoShortcutProviderMangledName: superwhisper_ios.SuperWhisperShortcuts

autoShortcuts:
  - actionIdentifier: ToggleRecordingIntent
    phraseTemplates: ["Toggle ${applicationName} Recording"]
    shortTitle: "Toggle Recording"
    systemImageName: record.circle
```

**This is the entire user-facing intent surface of the app.** One Toggle. The `releaseMic` parameter is what exposes their warm-mode timeout vs immediate release toggle. The `modeName` parameter is for their "modes" feature (different prompt configurations) — we don't have anything like that yet, can be optional.

`SuperWhisperShortcuts: AppShortcutsProvider` auto-registers the intent in Shortcuts.app with the phrase `Toggle Superwhisper Recording` — so users can say "Hey Siri, toggle Superwhisper Recording" or invoke via the Shortcuts URL.

## Raw findings — supporting extensions

### `superwhisper-share.appex` — share extension

Identical signing/App Group setup. Activation rule: accepts `Audio` (1 max) and `File` (1 max). So you can share an audio file from another app into Superwhisper for transcription. We don't have this; not blocking for the keyboard path.

### `superwhisper-activity.appex` — Live Activity

Surprisingly, **no App Group entitlement** on this extension. That means their Live Activity is read-only display, not cross-process state. They probably push everything via `ActivityKit.update(...)` from the main app. Same shape we use.

## What Superwhisper does NOT do

- **No AASA file** at `superwhisper.com/.well-known/apple-app-site-association` (returns 404). They DO NOT use Universal Links. Their cold-start path is the custom `superwhisper://` scheme.
- **No `applinks:`** entitlement on either main app or keyboard.
- **No private entitlements** beyond Push-to-Talk.
- **No LSApplicationQueriesSchemes** (couldn't verify the full Info.plist but it's not in the keys we sampled).

So the "Universal Links" rabbit hole we went down yesterday was a complete dead end. Confirmed by their actual implementation.

## The intent skeleton — what `ToggleRecordingIntent.swift` looks like

```swift
import AppIntents
import AVFoundation

struct ToggleRecordingIntent: AppIntent, AudioRecordingIntent, SessionStartingIntent {
    static var title: LocalizedStringResource = "Toggle Recording"
    static var description = IntentDescription("Toggle a Shhhcribble recording")
    static var openAppWhenRun: Bool = false
    static var isDiscoverable: Bool = true

    @Parameter(title: "Mode Name")
    var modeName: String?

    @Parameter(
        title: "Release Mic Immediately",
        description: "Release the mic immediately instead of honoring the app's session timeout.",
        default: false
    )
    var releaseMic: Bool

    @MainActor
    func perform() async throws -> some IntentResult & ReturnsValue<String> {
        let service = TranscriptionService.shared
        let status = TranscriptionStatus.shared

        if status.isRecording {
            // Stop and return the transcript.
            let transcript = try await service.stopAndReturnTranscript()
            if releaseMic { AudioSessionManager.shared.exitWarmMode() }
            return .result(value: transcript)
        } else {
            // Start. Don't wait for the recording to finish here —
            // the Shortcut should invoke us a second time to stop.
            try await service.startBackgroundRecording(modeName: modeName)
            return .result(value: "")
        }
    }
}
```

`AudioRecordingIntent` and `SessionStartingIntent` are marker protocols on `AppIntent` — declaring them tells iOS this intent needs mic access and signals lifecycle. Apple documents them in [AppIntents](https://developer.apple.com/documentation/appintents/audiorecordingintent).

`TranscriptionService` needs a couple of new methods:
- `startBackgroundRecording(modeName: String?) async throws` — starts recording without expecting a foreground UI.
- `stopAndReturnTranscript() async throws -> String` — finalises and returns the transcript.

## The Shortcut

Once we ship the AppIntent and bump the app, iOS auto-registers it in Shortcuts because of the `AppShortcutsProvider`. The user can find "Toggle Shhhcribble Recording" in the Shortcuts gallery.

We probably also want to ship a more useful Shortcut named explicitly "Shhhcribble Dictate" that:
1. Runs `ToggleRecordingIntent` (start)
2. Waits a beat
3. Runs `ToggleRecordingIntent` (stop) — returns transcript
4. Copies result to clipboard
5. (Optionally) shows a notification

For Superwhisper, the auto-shortcut name was `Toggle Superwhisper Recording`. The keyboard then fires `shortcuts://run-shortcut?name=Toggle%20Superwhisper%20Recording` — which Shortcuts.app opens, runs the intent, and (because `openAppWhenRun: false`) doesn't switch apps.

## Open questions worth tracking

1. **Why does Superwhisper's cold-start `extensionContext.open(superwhisper://...)` succeed when ours doesn't?** Both have identical entitlements. Possible causes:
   - App Store Distribution signing vs our Apple Development signing
   - iOS "trust" heuristic for established bundles
   - Their `extensionContext.open` may use a UIKit-wired button vs our SwiftUI tap gesture
   - PushToTalk entitlement on the main app may grant additional trust to the bundle
2. **What does `SessionStartingIntent` actually do?** Apple's docs are thin. It may grant additional background-execution time. Worth a 30-min read of the headers.
3. **Does the PushToTalk entitlement application require an existing live audio session demo?** The Apple form might ask for documentation. Need to draft.
4. **Can we ship Tier 1 alone, in the App Store, and ramp Tier 2 later?** Almost certainly yes — Tier 1 is "AppIntents + Shortcuts" which is a perfectly normal feature on iOS.

```bash
# Install ipatool

mkdir -p /tmp/sw-ipa && cd /tmp/sw-ipa

# Inspect
unzip -q com.superduper.superwhisper-ios_*.ipa
cd Payload/superwhisper-ios.app

plutil -p PlugIns/superwhisper-keyboard.appex/Info.plist | less
cat Metadata.appintents/extract.actionsdata | python3 -m json.tool | less
```
